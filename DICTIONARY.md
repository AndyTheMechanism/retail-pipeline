# Словарь таблиц и колонок

Собран из описаний в yml командой `make dictionary`. Руками не правится:
правка потеряется при следующей сборке. Менять надо описание рядом с
колонкой - там же, где стоят ее проверки.

Объектов: 21, колонок: 149. Колонок без описания: 0 - сборка словаря
падает, если их больше нуля.

Линейдж - `make docs`: dbt поднимает браузер, где видно, какая модель из
чего собрана. Рисовать эту картинку руками нельзя - она разъедется с кодом
в первую же неделю.

## Сырой слой - схема `raw`

Выгрузка источника как она есть, вместе с дефектами. Первичных ключей и ограничений уникальности здесь нет намеренно.

### `raw.cancellations`

*таблица*

Отмены. Партиция по cancelled_date, он на 0-2 дня позже даты заказа.

| Колонка | Тип | Что это |
|---|---|---|
| `cancellation_id` | bigint | Идентификатор отмены. Совпадает с идентификатором заказа. |
| `order_id` | bigint | Отмененный заказ. |
| `order_date` | date | Дата исходного заказа. |
| `cancelled_date` | date | Дата отмены. Ключ партиции. У заказов последних двух дней горизонта строки отмены может не быть - ее время не пришло, и проверки это учитывают. |
| `reason` | text | Причина отмены из источника - одна из четырех. |

### `raw.order_items`

*таблица*

Позиции заказа. Партиция по order_date. Здесь лежат дубли выгрузки и выбросы.

| Колонка | Тип | Что это |
|---|---|---|
| `order_id` | bigint | Заказ, к которому относится позиция. |
| `order_date` | date | Дата заказа, денормализована намеренно: без нее удаление партиции пришлось бы делать джойном к заказам. |
| `line_no` | integer | Номер позиции внутри заказа. Вместе с order_id образует зерно. |
| `sku` | text | Непрозрачный код позиции. Ни категории, ни бренда, ни закупочной цены здесь нет и не будет - это категорийный менеджмент, другая профессия. |
| `quantity` | integer | Количество. Ноль встречается - это заложенный выброс. |
| `unit_price` | numeric(10,2) | Цена за единицу, от 199 до 19990. |
| `line_amount` | numeric(12,2) | Сумма позиции. Может быть отрицательной - это тоже заложенный выброс, и он намеренно доезжает до витрины. |

### `raw.orders`

*таблица*

Заказы. Партиция по order_date. Статус проставлен уже в источнике.

| Колонка | Тип | Что это |
|---|---|---|
| `order_id` | bigint | Идентификатор заказа. Кодирует дату и магазин, поэтому по нему однозначно восстанавливается партиция, а возврат связывается с заказом без обращения к таблице заказов. |
| `store_id` | integer | Магазин, оформивший заказ. |
| `order_ts` | timestamp without time zone | Отметка времени заказа, час от 9 до 21. Витринами не используется - зерно дневное. |
| `order_date` | date | Дата заказа. Ключ партиции. |
| `channel` | text | Канал - офлайн, сайт или приложение. К дверному счетчику относится только офлайн, и из-за этого канал участвует в расчете конверсии. |
| `status` | text | Оформлен или отменен. Статус финален уже в источнике: отмена никогда не меняет вчерашнее число. |
| `customer_id` | bigint | Идентификатор покупателя, заполнен у 70% заказов. Оставлен как задел под когорты; ни одна текущая витрина его не использует. |

### `raw.returns`

*таблица*

Возвраты. Партиция по returned_date, а не по дате заказа: возврат приезжает своим днем и меняет выручку прошлого.

| Колонка | Тип | Что это |
|---|---|---|
| `return_id` | bigint | Идентификатор возврата, выводится из идентификатора заказа. |
| `order_id` | bigint | Заказ, к которому относится возврат. |
| `order_date` | date | Дата исходного заказа. К ней возврат относится в витрине продаж. |
| `line_no` | integer | Позиция заказа, которую вернули. |
| `returned_date` | date | Дата приезда возврата. Ключ партиции. Отстает от даты заказа на 0-30 дней, медиана 2 дня. |
| `quantity` | integer | Возвращенное количество, не больше купленного. |
| `returned_amount` | numeric(12,2) | Сумма возврата - цена за единицу на возвращенное количество. |

### `raw.store_traffic`

*таблица*

Дневной трафик точек. Партиция по traffic_date. Знаменатель конверсии.

| Колонка | Тип | Что это |
|---|---|---|
| `store_id` | integer | Магазин. |
| `traffic_date` | date | Дата. Ключ партиции. |
| `visitors` | integer | Посетители по дверному счетчику. Ноль означает не отсутствие людей, а неработающий прибор, и суждение об этом выносит флаг качества. |

### `raw.stores`

*таблица*

Справочник магазинов. Единственная таблица без партиций, перегружается целиком.

| Колонка | Тип | Что это |
|---|---|---|
| `store_id` | integer | Идентификатор магазина. Сквозной по всему проекту. |
| `store_code` | text | Код точки в виде S0001. Витринами не используется, живет для читаемости. |
| `city` | text | Город. Один из тридцати, справочный атрибут. |
| `store_format` | text | Формат точки - малый, средний или большой. Определяет базовый поток заказов. |
| `opened_on` | date | Дата открытия. До нее у магазина нет ни заказов, ни трафика, и на ней стоит зерно обеих витрин: 12 магазинов из 120 открылись внутри горизонта, и их пустые дни - не пропущенные данные. |

## Слой staging - схема `staging`

Приведение формы: типы, имена, зерно. Ничего не считает и не чинит. Материализован представлениями.

### `staging.stg_cancellations`

*представление*

Отмены. Витринами не используется намеренно: статус уже есть в заказе. Нужна для проверки ссылочной целостности и согласия с orders.status.

| Колонка | Тип | Что это |
|---|---|---|
| `cancellation_id` | bigint | Идентификатор отмены. Совпадает с идентификатором заказа. |
| `order_id` | bigint | Отмененный заказ. |
| `order_date` | date | Дата исходного заказа. |
| `cancelled_date` | date | Дата отмены, на 0-2 дня позже даты заказа. |
| `reason` | text | Причина отмены из источника - одна из четырех. |

### `staging.stg_order_items`

*представление*

Позиции заказа, по одной строке на позицию. Единственное место, где восстанавливается зерно (order_id, line_no) после дублей выгрузки.

| Колонка | Тип | Что это |
|---|---|---|
| `order_id` | bigint | Заказ, к которому относится позиция. |
| `order_date` | date | Дата заказа, денормализованная в позицию как ключ партиции. Входит в partition by оконных функций ради плана запроса - см. QUERY-PLAN.md. |
| `line_no` | integer | Номер позиции внутри заказа. Вместе с order_id образует зерно. |
| `sku` | text | Непрозрачный код позиции. Ни категории, ни бренда, ни закупочной цены здесь нет и не будет - это категорийный менеджмент, другая профессия. |
| `quantity` | integer | Количество. Ноль встречается - это заложенный выброс. |
| `unit_price` | numeric(10,2) | Цена за единицу, от 199 до 19990. |
| `line_amount` | numeric(12,2) | Сумма позиции. Может быть отрицательной: выбросы намеренно не отфильтрованы, и знак здесь не проверяется - их ловит флаг, а не гейт. |
| `source_copies` | bigint | Сколько строк на эту позицию было в источнике. Единица - норма, больше единицы означает дубль выгрузки. Колонка делает дедупликацию проверяемым фактом, а не подразумеваемой. |

### `staging.stg_orders`

*представление*

Шапка чека. Зерно - order_id.

| Колонка | Тип | Что это |
|---|---|---|
| `order_id` | bigint | Идентификатор заказа. Кодирует дату и магазин. |
| `store_id` | integer | Магазин, оформивший заказ. |
| `order_ts` | timestamp without time zone | Отметка времени заказа. Витринами не используется - зерно дневное. |
| `order_date` | date | Дата заказа, ключ партиции в сыром слое. |
| `channel` | text | Значение источника, "офлайн", "сайт" или "приложение". |
| `status` | text | Значение источника, "оформлен" или "отменен". |
| `customer_id` | bigint | Идентификатор покупателя, заполнен у 70% заказов. Задел под когорты; ни одна текущая витрина его не использует. |
| `is_cancelled` | boolean | Признак отмены. Отмененный заказ не дает ни выручки, ни возвратов. |
| `is_offline` | boolean | Признак офлайн-заказа. Числитель конверсии считается только по нему - дверной счетчик не видит ни сайт, ни приложение. |

### `staging.stg_returns`

*представление*

Возвраты. Зерно - return_id.

| Колонка | Тип | Что это |
|---|---|---|
| `return_id` | bigint | Идентификатор возврата, выводится из идентификатора заказа. |
| `order_id` | bigint | Заказ, к которому относится возврат. |
| `order_date` | date | Дата исходного заказа. К ней возврат относится в витрине продаж. |
| `line_no` | integer | Позиция заказа, которую вернули. |
| `returned_date` | date | Дата приезда возврата. По ней нарезана партиция в сыром слое. |
| `quantity` | integer | Возвращенное количество, не больше купленного. |
| `returned_amount` | numeric(12,2) | Сумма возврата. Именно она вычитается из выручки дня покупки. |
| `delay_days` | integer | Задержка возврата в днях. Медиана 2, 95-й перцентиль 19, 99-й 28, максимум 30. На этом числе стоит размер окна пересчета. |

### `staging.stg_store_traffic`

*представление*

Дневной трафик точек. Зерно - (store_id, traffic_date).

| Колонка | Тип | Что это |
|---|---|---|
| `store_id` | integer | Магазин. |
| `traffic_date` | date | Дата наблюдения трафика. |
| `visitors` | integer | Посетители по дверному счетчику. Ноль здесь не приводится к null и не считается ошибкой: суждение о том, считал ли прибор, выносит флаг качества, где рядом видны чеки. |

### `staging.stg_stores`

*представление*

Справочник магазинов. Зерно - store_id.

| Колонка | Тип | Что это |
|---|---|---|
| `store_id` | integer | Идентификатор магазина. Сквозной по всему проекту. |
| `store_code` | text | Код точки в виде S0001. Витринами не используется, живет для читаемости. |
| `city` | text | Город. Один из тридцати, справочный атрибут. |
| `store_format` | text | Формат точки - малый, средний или большой. Определяет базовый поток заказов. |
| `opened_on` | date | Дата открытия. До нее у магазина нет ни заказов, ни трафика, и на этом стоит зерно витрин: 12 магазинов из 120 открылись внутри горизонта, и их пустые дни - не пропущенные данные. |

## Промежуточный слой - схема `intermediate`

Сведение источников. Оставляет видимым все, включая сироты, чтобы гейту было что ловить.

### `intermediate.int_order_lines`

*таблица*

Позиция заказа вместе с шапкой. Зерно - (order_id, line_no). Инкрементальная: прогон трогает ровно целевую дату, и это решение принято по замеру плана запроса - см. QUERY-PLAN.md.

| Колонка | Тип | Что это |
|---|---|---|
| `order_id` | bigint | Заказ, к которому относится позиция. |
| `line_no` | integer | Номер позиции внутри заказа. Вместе с order_id образует зерно. |
| `order_date` | date | Дата из позиции, а не из шапки: в сыром слое это ключ партиции, и он есть даже у осиротевшей строки. Совпадение с датой шапки - инвариант, и проверяется он тестом, а не навязывается джойном. По этой же колонке режется окно пересчета и стоит индекс. |
| `store_id` | integer | Магазин из шапки заказа. Джойн левый намеренно, чтобы позиция без заказа не исчезла до проверки - и вот эта проверка. Null здесь означает позицию-сироту, и считать по ней выручку нельзя. |
| `channel` | text | Канал заказа из шапки. Витриной продаж не используется, нужен для разборов. |
| `is_cancelled` | boolean | Признак отмены из шапки. Отмененные не дают выручки. |
| `is_offline` | boolean | Признак офлайн-заказа из шапки. |
| `sku` | text | Непрозрачный код позиции. За пределы этой модели не выходит. |
| `quantity` | integer | Количество. Ноль встречается - заложенный выброс. |
| `unit_price` | numeric(10,2) | Цена за единицу. |
| `line_amount` | numeric(12,2) | Сумма позиции. Отрицательные значения не отфильтрованы намеренно. |
| `source_copies` | bigint | Сколько строк на эту позицию было в источнике до дедупликации. |

### `intermediate.int_returns_attributed`

*таблица*

Возврат, привязанный к магазину через свой заказ. Зерно - return_id. Модель обязательна, а не декоративна: в сыром слое возвратов нет store_id.

| Колонка | Тип | Что это |
|---|---|---|
| `return_id` | bigint | Идентификатор возврата. |
| `order_id` | bigint | Заказ, к которому относится возврат. |
| `line_no` | integer | Возвращенная позиция заказа. |
| `store_id` | integer | Магазин из заказа. Null означает возврат-сироту: сумма вычиталась бы из выручки неизвестно чего. |
| `is_cancelled` | boolean | Признак отмены исходного заказа. Возврат к отмененному заказу невозможен по смыслу - это проверяет отдельный тест assert_returns_belong_to_live_orders. |
| `order_date` | date | Дата исходного заказа. К ней возврат относится в витрине продаж. |
| `returned_date` | date | Дата приезда возврата. По ней видно, откуда взялось изменение вчерашнего числа. |
| `delay_days` | integer | Задержка возврата в днях. Вход для размера окна пересчета и для флага. |
| `quantity` | integer | Возвращенное количество. |
| `returned_amount` | numeric(12,2) | Сумма возврата. |

### `intermediate.int_store_day_spine`

*таблица*

Плотная решетка "магазин на день" от даты открытия магазина. Зерно - (store_id, calendar_date), ровно 62 690 строк. Зерно обеих витрин.

| Колонка | Тип | Что это |
|---|---|---|
| `store_id` | integer | Магазин. В решетке присутствуют все 120. |
| `calendar_date` | date | День горизонта. Горизонт вычисляется из наблюдаемых данных, а не берется константой: константа разъехалась бы с генератором молча. |

## Витрины - схема `marts`

То, что читает человек и дашборд.

### `marts.mart_store_daily_conversion`

*таблица*

Конверсия по магазину и дню. Зерно - (store_id, traffic_date), те же 62 690 строк. Окна пересчета у этой витрины нет: ни трафик, ни заказы задним числом не переписываются.

| Колонка | Тип | Что это |
|---|---|---|
| `store_id` | integer | Магазин. Часть зерна. |
| `traffic_date` | date | День наблюдения. Часть зерна. |
| `has_traffic` | boolean | Приехал ли трафик за этот день. Ложь означает непришедшую партицию. |
| `has_orders` | boolean | Приехали ли заказы за этот день. |
| `visitors` | integer | Посетители по дверному счетчику. Null, если трафик за день не приехал. |
| `orders_offline` | bigint | Чеки: офлайн-заказы без отмененных. Сайт и приложение не входят - дверной счетчик их не видит. |
| `conversion` | numeric | Чеки на посетителя. Null, если нет трафика, нет заказов или посетителей ноль: ноль посетителей при живых чеках - это сообщение о сломанном приборе, а не значение. Порог качества здесь не применяется - его выносит флаг. |

### `marts.mart_store_daily_quality`

*таблица*

Флаги качества: что в этот день у этого магазина считать нельзя. Зерно - (store_id, flag_date, check_name). Отдельная таблица, а не колонки в витринах: флагов бывает несколько на строку, они добавляются со временем, и строкой это растет естественно, а колонкой - нет.

| Колонка | Тип | Что это |
|---|---|---|
| `store_id` | integer | Магазин, к которому относится флаг. |
| `flag_date` | date | День, к которому относится флаг. Часть зерна. |
| `check_name` | text | Имя проверки. Английское, потому что по нему фильтруют и джойнят. Список закрытый: новый флаг добавляется осознанно, вместе с правкой этого теста, а не приезжает опечаткой. |
| `reason` | text | Причина по-русски - ее читает человек в отчете, а не машина. |
| `measured_value` | numeric | Число, из-за которого флаг сработал. |
| `threshold_value` | numeric | Порог, с которым сравнивали. Пусто там, где сравнения не было. |

### `marts.mart_store_daily_revisions`

*представление*

Журнал ревизий: какое опубликованное число изменилось, когда и почему. Ядро проекта. Строка появляется только у той пары "магазин и день", чье число действительно поехало; первая версия ревизией не считается. Представление поверх снимка ops.snap_store_daily_sales.

| Колонка | Тип | Что это |
|---|---|---|
| `store_id` | integer | Магазин, чье число пересчиталось. |
| `order_date` | date | День, за который изменилось число, а не день пересчета. |
| `revised_at` | timestamp without time zone | Когда пересчет это изменение внес. |
| `version_no` | bigint | Номер версии значения. Всегда больше единицы: первая версия - это не изменение, а первое появление числа. |
| `revenue_net_was` | numeric | Что было опубликовано до пересчета. |
| `revenue_net_became` | numeric | Что опубликовано после. |
| `revenue_net_delta` | numeric | Насколько сдвинулось. Отрицательное - число уменьшилось. |
| `returns_amount_was` | numeric | Возвраты, отнесенные к этому дню, до пересчета. |
| `returns_amount_became` | numeric | Они же после. Разница с предыдущей колонкой обычно и есть вся ревизия. |
| `reason` | text | Причина не угадывается, а выводится из того, какие величины разошлись. Возвраты изменились при неизменном брутто - поздний возврат, штатная жизнь домена. Изменилось брутто - пересобрано сырье, и это уже повод посмотреть, почему. |

### `marts.mart_store_daily_sales`

*таблица*

Продажи по магазину и дню. Зерно - (store_id, order_date), 62 690 строк по спайну. Возврат отнесен к дате заказа, поэтому вчерашнее число может измениться - в этом и предмет проекта.

| Колонка | Тип | Что это |
|---|---|---|
| `store_id` | integer | Магазин. Часть зерна. |
| `order_date` | date | День покупки. Часть зерна. Возвраты относятся именно к нему, а не ко дню своего приезда, и поэтому строка может быть переписана позже. |
| `has_orders` | boolean | Приехали ли заказы за этот день. Для открытого магазина это норма; ложь по всей сети в один день означает непришедшую партицию. |
| `orders_count` | bigint | Заказы без отмененных, по шапкам, а не по позициям. |
| `orders_cancelled_count` | bigint | Отмененные заказы. Вынесены отдельно, а не выброшены: день, где половина заказов отменилась, обязан отличаться от дня без заказов. |
| `lines_count` | bigint | Позиции в неотмененных заказах, уже после дедупликации. |
| `units_sold` | bigint | Проданные штуки в неотмененных заказах. |
| `revenue_gross` | numeric | Выручка по неотмененным заказам. Null, если данные за день не приехали - ноль ставится только там, где было что считать. |
| `returns_amount` | numeric | Возвраты, отнесенные к дате заказа. Именно они двигают вчерашнее число, и ради них существует окно пересчета. |
| `returns_arrived_amount` | numeric | Возвраты, приехавшие в этот день к заказам любых дат. В выручке не участвует; нужна, чтобы было видно, откуда взялось изменение прошлого. |
| `revenue_net` | numeric | Выручка за вычетом возвратов, отнесенных к дате заказа. |

### `marts.mart_store_daily_sales_trend`

*таблица*

Недельный фон выручки поверх витрины продаж. Отдельная модель, потому что скользящее окно перетягивает соседние строки, а витрина продаж инкрементальная.

| Колонка | Тип | Что это |
|---|---|---|
| `store_id` | integer | Магазин. Часть зерна. |
| `order_date` | date | День покупки. Часть зерна. |
| `revenue_net` | numeric | Чистая выручка дня, перенесена из витрины продаж для удобства чтения. |
| `revenue_net_avg_7d` | numeric | Скользящее среднее чистой выручки за 7 дней. Пусто, если в окне есть день без данных: avg пропустил бы null и поделил на меньшее число дней, то есть подменил бы пропуск оценкой. |

## Служебное - схема `ops`

Механика, на которой стоит журнал ревизий. Читать руками не нужно.

### `ops.snap_store_daily_sales`

*таблица*

История опубликованных значений витрины продаж. Служебная таблица, живет в схеме ops; читать ее руками не нужно - для этого есть marts.mart_store_daily_revisions.

| Колонка | Тип | Что это |
|---|---|---|
| `store_id` | integer | Магазин. Часть ключа снимка. |
| `order_date` | date | День покупки. Часть ключа снимка. |
| `has_orders` | boolean | Приехали ли заказы за этот день. За изменениями не следим. |
| `orders_count` | bigint | Заказы без отмененных. Одна из четырех отслеживаемых величин. |
| `orders_cancelled_count` | bigint | Отмененные заказы. За изменениями не следим. |
| `lines_count` | bigint | Позиции после дедупликации. За изменениями не следим. |
| `units_sold` | bigint | Проданные штуки. За изменениями не следим. |
| `revenue_gross` | numeric | Выручка брутто. Одна из четырех отслеживаемых величин. |
| `returns_amount` | numeric | Возвраты к дате заказа. Одна из четырех отслеживаемых величин и обычно единственная, которая двигается. |
| `returns_arrived_amount` | numeric | Возвраты по дате приезда. За изменениями не следим. |
| `revenue_net` | numeric | Выручка нетто. Одна из четырех отслеживаемых величин. |
| `dbt_scd_id` | text | Служебный идентификатор версии, ставит dbt. |
| `dbt_updated_at` | timestamp without time zone | Служебная отметка времени версии, ставит dbt. |
| `dbt_valid_from` | timestamp without time zone | С какого момента версия действует. Именно она становится датой пересчета в журнале ревизий. |
| `dbt_valid_to` | timestamp without time zone | До какого момента версия действовала. Пусто у текущей версии - той, что сейчас лежит в витрине. |
